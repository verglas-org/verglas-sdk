These recipes adapt established streaming and lakehouse patterns to the Verglas
component model. Instead of provisioning a cluster, assign each responsibility
to a Worker, Durable Object, Stream, Pipeline, or built-in state binding.

## Pattern translation

| Conventional data platform | Verglas component |
| --- | --- |
| Ingestion service | Worker + Stream binding |
| Partitioned stateful operator | Named Durable Object |
| Streaming transform job | Pipeline SQL |
| Retry/checkpoint database | Pipeline Durable Object |
| Data-lake writer | Sink + Catalog |
| Serving database or materialized view | Query Durable Object |
| Vector database | Vectorize binding |

## Sources behind the patterns

The recipes are original Verglas implementations informed by the official
documentation for [Databricks medallion
architecture](https://docs.databricks.com/aws/en/lakehouse/medallion), [Apache
Flink deduplication](https://nightlies.apache.org/flink/flink-docs-stable/docs/sql/reference/queries/deduplication/),
[Apache Iceberg table
maintenance](https://iceberg.apache.org/docs/latest/flink-maintenance/), and
[Cloudflare Vectorize](https://developers.cloudflare.com/vectorize/). They copy
the useful architectural ideas, not vendor-specific cluster or job machinery.
